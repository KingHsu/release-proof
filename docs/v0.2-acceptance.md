# v0.2 acceptance criteria

- [x] Online and fake model planners emit structured `call_tool` / `request_input` / `finish` actions; no model has direct executor access.
- [x] Every planner-selected Git/report read is admitted through the typed harness and traced with `planner_selected`, stable action key, and outcome.
- [x] Unknown tools, invalid arguments/paths, duplicate actions, elapsed time, no progress, and model/tool/step limits stop or pause without approval-equivalent output.
- [x] Interrupt/resume preserves evidence, action keys, counters, and a persistent execution deadline that is extended only by measured human-pause time.
- [x] A criterion is supported only when separately matched implementation and passing verification evidence satisfy explainable score/type constraints.
- [x] Test and CI evidence must declare an explicit passing conclusion; missing or unknown status fails closed.
- [x] Model-backed specialists can select only evidence IDs from their bounded candidate pack; unknown or hash-invalid references cannot enter the final report.
- [x] `--requirement` and `--requirement-file` are mutually exclusive, and an external requirement file is bounded, UTF-8, non-symlinked, non-secret-like, and recorded without its absolute host path.
- [x] Auto mode stays single for simple changes and enables specialists only after deterministic independent-domain eligibility.
- [x] The release-readiness Skill invokes the installed CLI, consumes matching JSON/Markdown artifacts, and removes only the temporary requirement file it created.
- [x] The Java review scanner reads the requested head commit in Git-ref mode and treats every static finding as a human evidence prompt, never approval.
